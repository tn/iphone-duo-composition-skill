# Useful compositions

Start with a task relationship, then choose its spatial expression. These are prompts for product judgment, not mandatory templates.

| Relationship | Useful example | Why it earns space |
| --- | --- | --- |
| Instruction + action | Demonstration beside the controls needed to follow it | Reduces switching while acting |
| Source + working draft | Original document alongside an editable interpretation | Makes checking and correction immediate |
| Comparison | Two selected photos, periods, or versions | Supports a real decision without memorizing the first item |
| Selection + consequence | Search results alongside the selected result's working view | Keeps browsing context while inspecting |
| Canvas + tools | A drawing or arrangement alongside its relevant controls | Leaves the artifact visible during adjustment |
| Performance + feedback | A practice session beside its current cue or feedback | Makes a hands-free task easier to follow |

Choose a relationship already supported by the product. Do not add a new analytics feature just to fill a pane. Avoid two equal-looking panels when one is clearly primary. An intentionally quiet secondary area is better than unrelated filler.

## Compose across configurations

Think of a sequence: phone task → expanded task with context → task arranged around a fold → phone task again. Keep labels, selection and the user's place recognizable. The expanded version should feel like the same product with more useful information available at once.

For a tabletop activity, consider which content is read from a distance and which actions are touched on the supported surface. For a book-like posture, consider whether each region can be read independently. Do not split a sentence, a primary button or a precision target across the bend.

Keep visual hierarchy deliberate: the expanded layout can show more context without making every component equally large. Adapt image crops and text measure; enlarging a portrait hero to fill a wide canvas can hide the subject and push the task away.

Sometimes the best expansion is one excellent canvas, a more useful grid, or a readable document. A second pane is optional. Likewise, folding is not a reason to hide functionality or invent an extra mode switch.

## Lessons from an existing workout app

Source and edited result proved useful together, as did previous and current records. The transferable lesson is the relationship, not the workout-specific screens.

A sidebar's nominal width did not guarantee that controls avoided the physical fold. Inspect the actual result before replacing a standard container; when replacement is justified, use region geometry rather than a guessed central gutter.

Recreating the navigation shell during a fold threatened unfinished forms. Keep the owning task and child identity stable, and let an already-open presentation finish without forcing a migration. A custom workspace, scene-local adoption flag or fixed width threshold used by one app is not a universal requirement.

These observations are project experience, not Apple platform guarantees. No application source or private data is included here.
